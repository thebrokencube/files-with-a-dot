# Human-Facing Writing

## Mechanics

Use separate bullets for separate ideas. State deploy impact when describing a shipped change. Define a domain term before reusing it. Put long walkthroughs, states, and migrations in `<details>`. Link an identifier with its title on first use.

Use direct modal language: `must` for a requirement and `can` for possibility or permission. Put the condition before the command. Use one noun for one concept. Lead with the outcome. Do not join an instruction to its rationale.

Write the answer first. Keep caveats only when they change the next action. Match a requested report, review, or artifact shape. Remove praise, recaps, filler, meta-commentary, and closing offers. Change the artifact rather than defend a taste decision.

## Audience

Use a diagram-first shape for sketches and comparisons. For leadership, give a goal, three bullets, and the relevant epic. For user-facing material, describe the newcomer journey. Jira work uses Context, Goal, and Scope. Peer-review notes remain grounded draft notes rather than polished prose.

## Shared Artifacts

Use the repository's documentation workflow for documentation changes. Do not expose internal planning paths or work-tracking identifiers in shared artifacts.

## Delegation

Include the mechanics above verbatim in a subagent prompt when the result will be human-facing. Built-in planning or exploration agents may not load repository guidance.
