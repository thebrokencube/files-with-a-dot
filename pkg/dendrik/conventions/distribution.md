# Distribution Convention

Dendrik separates portable agent content from native harness delivery. A generated file is not proof
that a harness is supported: each native adapter must be validated and exercised through its actual
installation and discovery surface.

## Support boundary

Claude Code is the proven marketplace adapter: it alone has a catalog, bundle, and installer.
Claude, default OMP, and Codex have separately admitted direct user roots for canonical policy and
Agent Skills. OMP additionally admits native terminal Ask, policy retention across terminal
compaction, and an isolated marketplace fallback; it has no generated marketplace catalog here.
Codex user skills are a sibling of app-owned `.system`, and its configuration is unmanaged.
Named OMP profiles, generic `~/.agents` roots, copied Codex catalogs, and unproved adapters emit
nothing.

## Portable kernel

- Agent Skills directories contain reusable workflow content and standard portable frontmatter.
- A repository-root `AGENTS.md` is portable project guidance; it is not automatically user-global
  configuration.
- Deterministic CLIs/scripts implement repeatable operations behind skills.
- Harness-specific fields, hooks, agents, settings, and manifests stay in native adapter surfaces.

## Registry and bundles

`plugins.json` is the authored inventory. Each entry is `{name, path, description}` and `path` names
a closed publishable root at `plugins/<name>`.

A CLI-backed Claude bundle contains only:

```text
plugins/<tool>/
  .claude-plugin/plugin.json
  skills/<tool>/SKILL.md
  skills/<tool>/references/ ...
  bin/setup
  VERSION
```

`cmd/<tool>` is the implementation root and is never a marketplace source. It owns Go source, tests,
module/build files, and the binary `VERSION`. The bundle `VERSION` is generated byte-for-byte from
that authority. The native Claude manifest owns the independent plugin version; binary bump implies
plugin bump, while plugin-only bumps remain valid.

## Generation and proof

`scripts/marketplace-generate` validates the registry and bundle sources, mirrors binary versions,
and emits only `.claude-plugin/marketplace.json`. Output validation checks Claude's native schema,
closed bundle contents, unsupported-artifact absence, and deterministic regeneration.

Support requires:

1. native strict validation;
2. isolated marketplace add/install and component inventory;
3. installed bundle closure inspection;
4. a live no-side-effect dogfood skill invocation;
5. network-free setup first-run and idempotency proof.

## Instructions and private overlays

Portable repository rules live in `AGENTS.md`; `CLAUDE.md` is a thin Claude-native adapter. Private
overlay files remain local `dot sync` inputs and never feed the public registry, bundles, generated
artifacts, or fixtures. Private OMP MCP configuration is mapped to the native user root without
publishing definition values or server names. Public/private destination collisions fail before any
symlink mutation without disclosing private source names or values.

## Adapter admission

Add a new adapter only after primary-contract research and isolated behavioral proof. Implement its
native artifact directly. Extract shared adapter machinery into Dendrik only after a second proven
adapter demonstrates real duplication; do not pre-design a generic runtime.
